## Why

Change 1 (`enforce-architecture-boundaries`) made the domain-facing contracts (`SessionPort`, `CredentialsPort`, `LibraryPort`, `DownloadsPort`) available for every platform to consume and documented, in `docs/architecture/composition-roots.md`, that Android's `AppContainer` is a real composition root only for data/catalog adapters. Session/auth and most feature ViewModels still fall back to non-production defaults. Verified against the current tree (`origin/main` at `5f44c21`):

- `androidApp/src/main/java/net/subsloth/MainActivity.kt:30` constructs `RootContainerViewModel` with the bare `viewModel()` factory, so `root.sessionPort` falls back to `core/domain/.../port/InMemorySessionState.kt` — it accepts any non-blank login/password pair and never persists across process death. `AppContainer.kt` constructs no `SessionPort` or `CredentialsPort` implementation at all.
- `core/domain/.../port/CredentialsPort.kt`'s own doc comment already claims "Implementations are provided by the Android shell using Android Keystore-backed encryption," but no such implementation exists. `core/preferences/build.gradle.kts` applies `subsloth.kmp.library` (no Android target), unlike `core/database/build.gradle.kts` (`subsloth.kmp.android.library`, with a real `androidMain` source set for `SubSlothDatabaseBuilder.android.kt`). `core/preferences/src/jvmMain/.../CredentialStore.kt` is a generic Java `KeyStore`/PKCS12 file-backed implementation intended for Desktop, not `android.security.keystore`; no `androidMain` actual exists.
- `openspec/specs/auth-security/spec.md`'s "Credential Storage Protection" requirement (added in the archived `2026-05-18-auth-persistence-shell` change, whose own `tasks.md` marks "Add Android Keystore-backed credential save/read/clear behavior" and "Run Android Keystore instrumented credential tests" as `[x]`) is not satisfied by the current tree — a documented-vs-actual discrepancy this change closes rather than papering over.
- `core/network/.../client/ClientFactory.kt:37-48` already supports authenticated clients (`create(login, password, ...)` installs Ktor `Auth { basic { ... } }`), but `AppContainer.kt:65-67` calls `ClientFactory.create()` with no arguments — the mechanism is built and unused.
- `androidApp/src/main/java/net/subsloth/SubSlothNavHost.kt:64` starts the authenticated nav host's own back stack at `rememberNavBackStack(LoginKey)`, whose `entry<LoginKey> { }` body (line 75-77) is empty. Since `SessionGate` (in `MainActivity.kt`) only renders `SubSlothNavHost()` after authentication, a freshly authenticated user lands on this nav host — whose first and only back-stack entry is a blank screen with no navigation ever pushed to `CatalogKey`. `entry<MovieDetailKey>`, `entry<ShowDetailKey>`, and `entry<AuthRepairKey>` (lines 94-100, 201-203) are likewise empty placeholder bodies.
- `feature/details/.../DetailViewModels.kt` already implements `MovieDetailViewModel`/`ShowDetailViewModel` in full — they are simply not constructed by the empty `MovieDetailKey`/`ShowDetailKey` nav entries. `feature/auth/.../LoginViewModel.kt` already models `LoginUiState.AuthRepair` and a `retryAuth()`/`dismissNeedsAuthRepair()` state machine, but no `AuthRepairScreen` composable exists and `AuthRepairKey`'s entry is empty.
- `SubSlothNavHost.kt` constructs `LibraryViewModel()`, `DownloadsViewModel()`, and `SettingsViewModel()` with zero arguments (lines 147, 163, 177), so every port callback falls back to its no-op/empty-success default. `core/database/.../LibraryPortAdapter.kt` (a real, session-scoped `LibraryPort` implementation) and `core/media/src/androidMain/.../DownloadController.kt` (a real, DAO-backed `DownloadsPort` implementation, built in the archived `2026-06-03-offline-downloads` change) both already exist and are never constructed by any composition root. `PlayerViewModel(mediaId, ...)` (line 126) receives a real `mediaId` but every other port parameter (`fetchVideoSource`, `fetchEpisodes`, `saveProgress`, etc.) defaults to a failure/empty-success no-op.
- `core/domain/.../port/SessionPort.kt` declares `open`/`close`/`invalidate` as plain (non-`suspend`) functions. A production Android adapter needs a `suspend` network call to validate credentials against the Kodi-compatible startup sequence (`auth-security`'s "Kodi Compatible Credential Validation" requirement) before it can honor `open()` — the current signature cannot express this without launching an un-awaited coroutine internally, which would make `Outcome.Success` observable before validation completes.
- `androidApp/src/androidTest/.../LoginFlowTest.kt` only exercises `LoginViewModel` against `InMemorySessionState` and a hand-rolled `FailingSessionPort`; no instrumented test exists for a real Keystore-backed adapter, cold start with a persisted session, expired-credential repair, or account switching.

## What Changes

- Add a real `androidMain` `CredentialStore` actual to `:core:preferences` (migrating its build to `subsloth.kmp.android.library`, mirroring `:core:database`'s pattern) backed by Android Keystore (API 26+ `android.security.keystore`), excluded from Auto Backup and device-to-device transfer, wired through the existing `CredentialsStoreAdapter`/`CredentialsPort`.
- Add an Android production `SessionPort` implementation that: recovers persisted credentials at cold start and attempts silent re-authentication before falling back to the login screen; performs the Kodi-compatible validation request via `Api`/`ClientFactory` on `open()`; returns `AuthError.InvalidCredentials` (never accepting a credential pair merely because both fields are non-blank) on rejection; clears encrypted credentials and in-memory state on `close()`/`invalidate()`.
- Change `SessionPort.open`, `close`, and `invalidate` to `suspend fun` (a `:core:domain` interface change) so a real adapter can await the network validation call and the encrypted-storage read/write/clear calls; update `InMemorySessionState` and every call site (`LoginViewModel`, `LibraryPortAdapter`'s `sessionPort.current()` reads stay non-suspend since `current()` is unaffected).
- Wire `AppContainer` to build and rebuild an authenticated `Api`/`ClientFactory` client (and the `CatalogRepository` that wraps it) whenever the session adapter's credentials change, and tear the authenticated client down on logout/invalidate.
- Fix `SubSlothNavHost`'s back stack to start at `CatalogKey` (not `LoginKey`) and remove the now-dead `entry<LoginKey>` — `SessionGate` already owns the login-vs-authenticated split at a level above this nav host, so an authenticated nav host never needs a login entry of its own.
- Wire the existing `MovieDetailViewModel`/`ShowDetailViewModel` into the `MovieDetailKey`/`ShowDetailKey` nav entries; implement an `AuthRepairScreen` composable backed by `LoginViewModel`'s existing `LoginUiState.AuthRepair` state and wire it into `AuthRepairKey`.
- Wire `LibraryViewModel`, `DownloadsViewModel`, `SettingsViewModel`, and `PlayerViewModel` through `AppContainer`-constructed real adapters: `LibraryPortAdapter` (already exists, unused), `DownloadController` (already exists, unused), direct `UserPreferences`/`CredentialsPort`/Room DAO calls for settings reads/writes and the three independent logout cleanup scopes, and the real catalog/video-source/progress ports for `PlayerViewModel`.
- Add account-switching support (logging out and logging back in as a different account re-derives the profile key and re-scopes account-scoped data per the existing `Persistence Scope Separation`/`Account Profile Key Derivation` requirements — no new storage mechanism, just real wiring exercising the existing derivation).
- Add instrumented Android tests for: valid login, invalid login (typed error, no session opened), cold start with a persisted session, expired-credential auth repair, logout (verifying the existing Logout Cleanup Scopes partitioning against real storage), and account switching.
- Add a test proving production Android startup constructs no `InMemorySessionState` and no ViewModel using its no-op port defaults.

## Capabilities

### Modified Capabilities

- `auth-security`: credential storage protection is backed by a real Android Keystore adapter instead of being unimplemented; adds authenticated-client lifecycle, cold-start recovery, and account-switching requirements; auth failure repair gets a real screen instead of a placeholder nav entry.
- `architecture`: `SessionPort`'s session-mutating functions become `suspend`; adds a requirement that the authenticated nav host starts at a real destination (not a placeholder) and that production Android composition excludes no-op/default ViewModel port bindings.

## Impact

- Affects `core/domain` (`SessionPort` signature), `core/preferences` (new `androidMain` source set and convention-plugin change), `androidApp` (`AppContainer`, `MainActivity`, `SubSlothNavHost`, new `AuthRepairScreen`), and touches `feature/auth`, `feature/library`, `feature/details`, `feature/player`, `feature/settings` only at their existing ViewModel constructor call sites (no ViewModel port shape changes expected — they already accept the real port signatures via their default-lambda parameters).
- `SessionPort.open`/`close`/`invalidate` becoming `suspend` is a source-breaking interface change; every implementation (`InMemorySessionState`, test fakes, the new Android adapter) and every call site must update in the same change.
- No change to Desktop or Web composition roots — they keep falling back to `InMemorySessionState` per `docs/architecture/composition-roots.md`, which Changes 3A/3B own.
- Risk: medium-high. This is the first change to touch real Android cryptography (Keystore) and the first suspend-signature change to a canonical domain port. Both are scoped with explicit verification (instrumented Keystore tests; full `:core:domain`/`:core:ui`/`feature:*` test suite after the signature change) before the rest of the wiring proceeds.
